1 Установка и структура проекта

Laravel — это готовая коробка для сайтов на PHP: поставил, и уже есть роуты, база, шаблоны и логин. Здесь — как его поставить и что где лежит.

  • Установка через Laravel Installer: composer create-project laravel/laravel app или laravel new app.
  • Требования: PHP 8.2+, Composer, Node/NPM (для Vite).
  • Ключевые папки: app/, routes/, resources/, public/, config/, database/.
  • .env — переменные окружения; .env.example — шаблон для коммита.
  • Запуск: php artisan serve → http://localhost:8000.
Создание проекта
composer create-project laravel/laravel myapp
cd myapp
copy .env.example .env      # Windows
php artisan key:generate
php artisan serve

2 Artisan CLI

Artisan — консоль-помощница. Одной командой создаёшь контроллер, модель, миграцию — не нужно руками плодить файлы и вспоминать пути.

  • Artisan — командная строка Laravel.
  • Генераторы: make:model, make:controller, make:migration, make:seeder, make:middleware.
  • Миграции: php artisan migrate, migrate:fresh, migrate:rollback.
  • Tinker — REPL для отладки: php artisan tinker.
  • Справка: php artisan list, php artisan help make:model.
  • Просмотр маршрутов: php artisan route:list.
  • Очистка кэша: php artisan optimize:clear.
Генерация ресурса целиком
php artisan make:model Post -mcr
# -m  миграция, -c контроллер, -r resource-контроллер

3 Конфигурация

Конфиги — файлики настроек: имя сайта, база данных, почта, кэш. Лежат в папке config, а секретные данные — в .env, который в git не коммитят.

  • Файлы настроек в config/: app.php, database.php, cache.php, queue.php, mail.php.
  • Доступ к настройкам: config() — config('app.name').
  • env() — чтение переменных окружения; не использовать в коде вне config-файлов.
  • APP_KEY — ключ шифрования, генерируется php artisan key:generate.
  • APP_DEBUG — показывать ли ошибки; в проде false.
  • Dotenv — парсер .env; не хранить секреты в коде.
Чтение настроек
config('app.name', 'Default');          // с дефолтом
config(['app.timezone' => 'UTC']);       // на лету
env('DB_DATABASE');                      // только в config-файлах

4 Маршрутизация

Маршрут — это правило «пользователь зашёл на /posts → открыть такой-то контроллер». Без них Laravel не поймёт, что показывать по какому URL.

  • Файлы: routes/web.php (сессии+CSRF), routes/api.php (префикс /api), routes/console.php.
  • Методы: Route::get, post, put, patch, delete, any, match.
  • Параметры: {id}, опциональные {id?}, где() ограничения.
  • Именованные маршруты — ->name('posts.show'), генерация route('posts.show', $id).
  • Группы: prefix, middleware, name.
  • Resource — 7 REST-методов разом; apiResource — 5.
  • Привязка модели — {post} автоматически даёт модель.
  • Route::fallback() — 404 для всего остального.
Маршруты
Route::get('/posts', [PostController::class, 'index'])->name('posts.index');
Route::get('/posts/{post}', [PostController::class, 'show'])->whereNumber('post');
Route::resource('posts', PostController::class);
Route::middleware('auth')->group(function () {
    Route::get('/profile', [ProfileController::class, 'show']);
});

5 Контроллеры

Контроллер — обработчик запроса: забрал данные, что-то сделал, вернул страницу или JSON. Главное правило: тонкие контроллеры, толстые модели.

  • Класс в app/Http/Controllers, методы = действия.
  • Resource-контроллер — готовые методы index/create/store/show/edit/update/destroy.
  • Single Action — один метод __invoke().
  • DI в методах — Laravel сам подставляет зависимости в методы контроллера.
  • Возврат: view(), redirect(), json(), response().
  • Ошибки: abort(404), abort_unless(), ModelNotFoundException.
Контроллер
class PostController extends Controller
{
    public function index()
    {
        return view('posts.index', [
            'posts' => Post::latest()->paginate(10)
        ]);
    }
    public function show(Post $post)
    {
        return view('posts.show', compact('post'));
    }
}

6 Middleware

Middleware — проверка на входе: вошёл ли пользователь, не спамит ли, не админ ли. Не прошёл — дальше не пускаем. Как охранник на проходной.

  • Middleware — фильтр HTTP-запросов до/после контроллера.
  • Встроенные: auth, guest, throttle, verified, signed, cache.headers.
  • Создание: php artisan make:middleware CheckRole.
  • Регистрация: bootstrap/app.php → ->withMiddleware().
  • Применение: в маршруте, группе или __construct контроллера.
  • Порядок выполнения: глобальные → групповые → маршрутные.
Middleware
class CheckRole
{
    public function handle(Request $request, Closure $next, string $role)
    {
        if (! $request->user()->hasRole($role)) {
            abort(403);
        }
        return $next($request);
    }
}
// Route::get('/admin', ...)->middleware('role:admin');

7 Eloquent ORM

Eloquent — работа с базой без голого SQL: модель = таблица, пишешь Post::where('active', 1)->get() — и готово. Самая главная тема Laravel, её спрашивают в первую очередь.

  • Модель = таблица БД. По умолчанию таблица — множественное число класса.
  • $fillable / $guarded — защита от массового присваивания.
  • Запросы: where(), orderBy(), limit(), find(), first(), get(), paginate().
  • findOrFail() / firstOrFail() → 404.
  • Отношения: hasOne, hasMany, belongsTo, belongsToMany, hasManyThrough, morphMany.
  • Eager Loading — with('comments') против N+1.
  • Локальные скопы — scopePublished().
  • Accessors/Mutators — getFullNameAttribute() / setPasswordAttribute().
  • SoftDeletes — мягкое удаление (deleted_at).
  • Casts — преобразование типов: array, json, date, boolean.
Модель и запрос
class Post extends Model
{
    use SoftDeletes;
    protected $fillable = ['title', 'body', 'user_id'];
    protected $casts = ['is_published' => 'boolean'];
    public function user() { return $this->belongsTo(User::class); }
    public function comments() { return $this->hasMany(Comment::class); }
}
$posts = Post::with('user:id,name')
    ->where('is_published', true)
    ->latest()->paginate(15);

8 Миграции

Миграции — история изменений структуры базы. Команда migrate накатывает таблицы; откатил, поправил, накатил заново. Так база у всей команды одинаковая.

  • Миграция — версионирование схемы БД.
  • Создание: php artisan make:migration create_posts_table.
  • Структура: up() (применение), down() (откат).
  • Schema Builder — Schema::create(), методы string(), integer(), foreignId().
  • Внешние ключи — $table->foreignId('user_id')->constrained().
  • Индексы — ->index(), ->unique().
  • Откаты: migrate:rollback (последний батч), migrate:fresh (всё заново).
Миграция
Schema::create('posts', function (Blueprint $table) {
    $table->id();
    $table->foreignId('user_id')->constrained()->cascadeOnDelete();
    $table->string('title')->unique();
    $table->text('body');
    $table->boolean('is_published')->default(false);
    $table->timestamps();
});

9 Сидеры (Seeders)

Сидеры — наполнители базы: кладут тестовых юзеров, посты, справочники, чтобы в разработке было с чем работать. Название от английского seed — «семена».

  • Заполнение БД тестовыми данными: php artisan make:seeder UserSeeder.
  • Запуск: php artisan db:seed, с конкретным: --class=UserSeeder.
  • DatabaseSeeder — вызывается по умолчанию, вызывает остальных.
  • В связке с миграциями: migrate:fresh --seed.
  • Данные через модели: User::factory()->count(10)->create().
Seeder
class DatabaseSeeder extends Seeder
{
    public function run(): void
    {
        $user = User::factory()->create([
            'name' => 'Admin',
            'email' => 'admin@test.dev',
        ]);
        Post::factory()->count(50)->for($user)->create();
    }
}

10 Фабрики (Factories)

Фабрики — генераторы фейковых данных: 50 постов с рандомными заголовками за секунду. Вместе с сидерами мгновенно наполняют базу.

  • Фабрика — генерация фейковых данных модели через Faker.
  • Создание: php artisan make:factory PostFactory.
  • definition() — массив атрибутов по умолчанию.
  • Состояния: state() — ->state(['x' => 1]).
  • Использование: Post::factory()->count(10)->create(), ->make() (без записи).
  • Связи в фабрике: 'user_id' => User::factory() или ->for($user).
Фабрика
class PostFactory extends Factory
{
    protected $model = Post::class;
    public function definition(): array
    {
        return [
            'user_id' => User::factory(),
            'title'   => fake()->sentence(),
            'body'    => fake()->paragraphs(3, true),
        ];
    }
}

11 Валидация запросов

Валидация — проверка того, что прислал пользователь: не пустое ли поле, не длиннее ли 255 символов, не занят ли email. Сразу показываем ошибки.

  • В контроллере: $request->validate() — возвращает отфильтрованные данные.
  • Form Request — класс с rules() и authorize().
  • Правила: required, max:255, email, unique:users, exists:posts,id.
  • Сложные: Rule:: классы, sometimes, nullable, confirmed.
  • Кастомные правила: Rule-объект или closure.
  • Ошибки → $errors bag в сессии, редирект назад.
  • Для API: 422 + ValidationException с JSON.
Form Request
class StorePostRequest extends FormRequest
{
    public function authorize(): bool { return true; }
    public function rules(): array
    {
        return [
            'title' => 'required|string|max:255',
            'body'  => 'required|string|min:10',
            'tags'  => 'array',
        ];
    }
}

12 Blade шаблоны

Blade — шаблоны страниц: обычный HTML, а внутрь вставляешь переменные {{ $name }} и циклы @foreach. Чтобы не мешать PHP с HTML в одном файле.

  • Blade — шаблонизатор Laravel; файлы *.blade.php.
  • Вывод: {{ $var }} (экранируется), {!! !!} (без экранирования).
  • Директивы: @if, @foreach, @forelse, @empty, @switch.
  • Наследование: @extends/@section/@yield.
  • Компоненты: <x-alert /> и слоты {{ $slot }}.
  • layouts/app.blade.php — общий макет.
  • Условные: @auth/@guest, @can.
  • CSRF: @csrf, метод-фейкер @method('PUT').
Blade
@extends('layouts.app')

@section('content')
  <h1>{{ $post->title }}</h1>
  <p>{!! $post->body !!}</p>
  @forelse ($post->comments as $comment)
    <div>{{ $comment->body }}</div>
  @empty
    <p>Комментариев нет</p>
  @endforelse
@endsection

13 Аутентификация (Auth)

Auth — система логина: регистрация, вход, выход, сброс пароля. Пароли хешируются, сессия запоминается, и это всё уже есть из коробки.

  • Стандартный скаффолдинг: auth:breeze или Jetstream/Fortify.
  • Хелперы: auth(), auth()->user(), auth()->check(), auth()->id().
  • Попытка входа: Auth::attempt(['email' => ..., 'password' => ...]).
  • Выход: Auth::logout() + инвалидация сессии.
  • Guard — способ проверки (web, api, sanctum).
  • Provider — источник пользователей (users, eloquent).
  • Защита паролей: Hash::make() / bcrypt().
  • Password Reset — сброс пароля по email.
  • Remember me: Auth::attempt($cred, true) — remember_token.
Логин
if (Auth::attempt([
    'email' => $request->email,
    'password' => $request->password,
], $request->boolean('remember'))) {
    $request->session()->regenerate();
    return redirect()->intended('/dashboard');
}
return back()->withErrors(['email' => 'Неверный логин']);

14 Авторизация

Авторизация — про права: «может ли этот юзер редактировать этот пост?». Gates и Policies отвечают на такие вопросы. Не путай с логином.

  • Gate — замыкания по способностям: Gate::define('update-post', ...).
  • Policy — класс правил для модели: PostPolicy.
  • Проверка: $this->authorize('update', $post), Gate::allows(), @can.
  • before() — правило для всех (например, админ).
  • Хелпер: $user->can() / cannot().
  • Ошибки: 403 / AuthorizationException.
  • Создание: php artisan make:policy PostPolicy --model=Post.
Policy
class PostPolicy
{
    public function update(User $user, Post $post)
    {
        return $user->id === $post->user_id;
    }
}
// в контроллере:
$this->authorize('update', $post);

15 Очереди (Queues)

Очереди — отложенные задачи: письма, отчёты, обработка картинок. Сайт не ждёт их и не тормозит: положил в очередь — и работаешь дальше.

  • Очередь — отложенное выполнение тяжёлых задач.
  • Job — класс задачи, make:job SendEmail.
  • Драйверы: sync, database, redis, sqs, beanstalkd.
  • Постановка: dispatch(new SendEmail($user)), Job::dispatch().
  • Запуск воркера: php artisan queue:work.
  • Приоритет: ->onQueue('high'), задержка ->delay(now()->addMinute()).
  • Ретраи: tries, backoff, failed-джобы → таблица failed_jobs.
  • Rate limiting — ShouldBeUnique для исключения дублей.
Job
class SendWelcomeEmail implements ShouldQueue
{
    public $tries = 3;
    public $backoff = [2, 10, 60];

    public function __construct(public User $user) {}

    public function handle(): void
    {
        Mail::to($this->user)->send(new WelcomeMail($this->user));
    }
}
dispatch(new SendWelcomeEmail($user))->delay(now()->addMinute());

16 События и слушатели

События — «что-то произошло» (пост создан), слушатели — «кто на это реагирует» (отправить уведомление). Развязывают куски кода между собой.

  • Event — класс-маркер о произошедшем действии.
  • Listener — реакция на событие (лог, почта, кэш).
  • Создание: php artisan make:event PostCreated, make:listener NotifyUsers.
  • Регистрация: EventServiceProvider / #[Listen] атрибут.
  • Вызов: event(new PostCreated($post)).
  • Асинхронность: реализовать ShouldQueue — слушатель уйдёт в очередь.
  • Broadcast — слушатели на фронте (WebSockets).
Событие + слушатель
class PostCreated
{
    public function __construct(public Post $post) {}
}
class SendNotification implements ShouldQueue
{
    public function handle(PostCreated $event): void
    {
        foreach ($event->post->followers as $follower) {
            $follower->notify(new NewPost($event->post));
        }
    }
}

17 Кэширование

Кэш — запоминание тяжёлых вычислений: посчитал один раз, сохранил в память, дальше отдаёшь всем мгновенно. База и сервер вздыхают с облегчением.

  • Драйверы: file, database, redis, memcached, array, null.
  • API: Cache::put('key', $value, 60), get, remember, forget.
  • TTL: секунды или Carbon-время.
  • Блокировки — Cache::lock('key', 10) для конкурентных задач.
  • Атомарные: increment/decrement — счётчики.
  • Кэш запросов: remember на тяжёлых выборках; теги для групп.
  • Кэш-фасад vs helpers: cache() хелпер.
Кэш запроса
$stats = Cache::remember('stats', now()->addHour(), function () {
    return DB::table('posts')
        ->selectRaw('count(*) as total')
        ->first();
});

18 REST API

API — способ отдавать данные другим приложениям (фронту, мобилке) в формате JSON по правилам REST. Всё, что видит фронтенд, может прийти отсюда.

  • Маршруты: routes/api.php, префикс /api.
  • Sanctum — токены API + SPA-аутентификация.
  • Passport — полный OAuth2.
  • Ответы: response()->json(), API Resource — PostResource.
  • Формат ошибок: API-исключения → JSON.
  • Версионирование: префикс /v1 или заголовок Accept.
  • Rate limit — throttle:api.
  • Пагинация JSON: paginate() в ресурсе.
API контроллер
Route::apiResource('posts', PostController::class)
    ->middleware('auth:sanctum');

class PostController extends Controller
{
    public function index(): PostResource
    {
        return PostResource::collection(Post::paginate(15));
    }
}

19 Почта (Mail)

Mail — отправка писем: приветственные, сброс пароля, статус заказа. Пишешь класс письма с шаблоном — и отправляй куда нужно.

  • Класс письма: make:mail OrderShipped, реализует ShouldQueue.
  • Драйверы: smtp, mailgun, ses, log (в файл при разработке).
  • Отправка: Mail::to($email)->send(new OrderShipped(...)).
  • Mailables — view, subject, attachements, headers.
  • Тест локально: Mailtrap, MAIL_MAILER=log.
  • Mailers — несколько конфигов в config/mail.php.
Mailable
class OrderShipped extends Mailable
{
    use Queueable, SerializesModels;

    public function __construct(public Order $order) {}

    public function envelope(): Envelope
    {
        return new Envelope(
            subject: 'Заказ отправлен №' . $this->order->id,
        );
    }
    public function content(): Content
    {
        return new Content(view: 'emails.order-shipped');
    }
}

20 Уведомления (Notifications)

Уведомления — «вас лайкнули». Одно уведомление, а доставить можно и на почту, и в базу, и в Telegram/Слак. Всё в одном классе.

  • Уведомления можно слать по нескольким каналам: mail, database, broadcast, sms, slack.
  • Класс: make:notification NewFollower.
  • Отправка: $user->notify(new NewFollower()) или Notification::send($users, $n).
  • Хранение: таблица notifications, viaDatabase().
  • On-demand — Notification::route('mail', 'email@x').
  • Отложенные: реализовать ShouldQueue.
Уведомление
class NewFollower extends Notification
{
    public function via($notifiable): array
    {
        return ['mail', 'database'];
    }
    public function toMail($notifiable): MailMessage
    {
        return (new MailMessage)
            ->line('У вас новый подписчик!')
            ->action('Открыть профиль', url('/profile'));
    }
    public function toDatabase($notifiable): array
    {
        return ['follower_id' => $this->follower->id];
    }
}

21 Broadcasting (WebSockets)

Broadcasting — живое обновление: сообщение прилетает на страницу без перезагрузки через WebSocket. Чаты, лайки, уведомления в реальном времени.

  • Broadcast — пуш событий клиенту в реальном времени.
  • Каналы: public/private/presence.
  • Сервер: Reverb (новый), pusher, ably, soketi.
  • Фронт: Laravel Echo (JS-клиент).
  • Событие с ShouldBroadcast + broadcastOn().
  • Авторизация каналов: routes/channels.php.
Broadcast-событие
class CommentCreated implements ShouldBroadcast
{
    use Dispatchable, InteractsWithSockets, SerializesModels;

    public function __construct(public Comment $comment) {}

    public function broadcastOn(): Channel
    {
        return new Channel('post.' . $this->comment->post_id);
    }
}
// JS: Echo.channel('post.1').listen('CommentCreated', cb);

22 Контейнер (DI Container)

Контейнер — умная фабрика объектов: попросил класс — он сам создал его вместе со всеми зависимостями. Основа всей магии DI в Laravel.

  • Контейнер — автоматическое разрешение зависимостей.
  • bind() — регистрация класса/интерфейса.
  • singleton() — один экземпляр на приложение.
  • Авторазрешение: типы в конструкторе подставляются автоматически.
  • Контекстные привязки — разный класс для разных потребителей.
  • Псевдонимы: alias().
  • Резолв: app(MyService::class) или app().
Привязки
app()->bind(PaymentGateway::class, StripeGateway::class);
app()->singleton(CartService::class);
app()->alias(CartService::class, 'cart');

class CheckoutController
{
    public function __construct(
        private PaymentGateway $gateway,   // авторазрешение
    ) {}
}

23 Service Providers

Провайдеры — точки старта приложения: место, где подключаются свои сервисы, слушатели и привязки. Почти всё в Laravel работает через них.

  • Service Provider — точка инициализации сервисов.
  • Жизненный цикл: register() (только привязки) → boot() (после регистрации всех).
  • Деферред: deferred — грузится по требованию.
  • Регистрация в bootstrap/providers.php.
  • Через провайдеры Laravel регистрирует почти всё: Events, RouteServiceProvider и т.д.
Provider
class AppServiceProvider extends ServiceProvider
{
    public function register(): void
    {
        $this->app->singleton(Logger::class, fn () => new Logger());
    }
    public function boot(): void
    {
        Model::preventLazyLoading(! app()->isProduction());
    }
}

24 Facades и макросы

Фасады — статические обёртки: пишешь Cache::put() вместо того, чтобы тянуть объект из контейнера. Коротко и удобно.

  • Facade — статичный прокси к сервису из контейнера.
  • Примеры: Cache, Mail, DB, Route, Auth.
  • Реальный класс: Cache::put(...) → app('cache.store').
  • Real-time facade — Facades\MyClass.
  • Макросы — расширение классов через Macroable: Str::macro(), Collection::macro().
  • Псевдонимы фасадов в config/app.php.
Макрос
use Illuminate\Support\Str;

Str::macro('slugWithId', function (string $title, int $id) {
    return Str::slug($title) . '-' . $id;
});

Str::slugWithId('Hello World', 7); // hello-world-7

25 Коллекции

Коллекции — прокачанные массивы: filter, map, reduce цепочками в одну строку. Вернулись из БД данные — работаешь с ними как с коллекцией.

  • Collection — обёртка над массивом с цепочками методов.
  • Популярные: map(), filter(), reduce(), sortBy(), groupBy(), pluck().
  • LazyCollection — ленивая генерация для больших данных.
  • Higher-order сообщения: $users->each->notify(...).
  • Преобразование: collect($array), ->toArray(), ->toJson().
  • Макро: Collection::macro().
Коллекции
$names = collect([
    ['name' => 'Анна', 'age' => 30],
    ['name' => 'Борис', 'age' => 25],
])
    ->filter(fn ($u) => $u['age'] >= 18)
    ->pluck('name')
    ->implode(', ');
// Анна, Борис

26 Тестирование

Тесты — автопроверки: написал один раз, потом запускаешь и знаешь, что ничего не сломалось. В Laravel это почти обязательная часть работы.

  • Фреймворк: PHPUnit (или Pest), по умолчанию phpunit.xml.
  • Feature тесты — весь стек (HTTP, БД), Unit — изолированно.
  • HTTP: $this->get('/posts'), ->assertOk(), ->assertSee().
  • БД: RefreshDatabase, DatabaseTransactions, фабрики.
  • Запуск: php artisan test.
  • Моки: Mail::fake(), Event::fake(), Queue::fake().
  • Покрытие: Xdebug + --coverage.
Feature-тест
class PostTest extends TestCase
{
    use RefreshDatabase;

    public function test_guest_cannot_create_post(): void
    {
        $response = $this->post('/posts', [
            'title' => 'Спам', 'body' => 'x',
        ]);
        $response->assertRedirect('/login');
    }
}

27 Архитектура и паттерны

Про то, как раскладывать код: не всё в контроллер, а сервисы, репозитории, DTO, action-классы. Чтобы проект рос и не превращался в кашу.

  • Базовая структура: MVC-подобная (Model-View-Controller).
  • Repository — слой доступа к данным.
  • Service — бизнес-логика вне контроллеров.
  • DTO — передача данных между слоями.
  • Action-классы — единая ответственность (один класс = одно действие).
  • Компромиссы: не перегружать тонким слоем, следить за размером контроллера.
  • Интерфейсы для тестируемости (mock-реализации).
Action
class CreateOrder
{
    public function __construct(
        private OrderRepository $orders,
        private Inventory $inventory,
    ) {}

    public function handle(array $data): Order
    {
        $this->inventory->reserve($data['items']);
        return $this->orders->create($data);
    }
}

28 Оптимизация

Ускорение сайта: убить N+1 запросы, закэшировать тяжёлое, поставить индексы. Страницы грузятся быстрее, сервер тратит меньше ресурсов.

  • Главная проблема: N+1 запросов — решается eager loading.
  • Профилирование: Debugbar / Telescope / query log.
  • Индексы БД для where/join.
  • Кэширование тяжёлых запросов: Cache::remember().
  • Отложенная загрузка запрещена: Model::preventLazyLoading() в dev.
  • select() только нужные колонки, chunk() для массовой обработки.
  • OPcache + php artisan optimize на проде.
  • Octane — высокопроизводительный сервер (Swoole/RoadRunner).
Anti N+1
// плохо: N запросов
$posts = Post::all();
foreach ($posts as $post) { $post->user->name; }

// хорошо: 2 запроса
$posts = Post::with('user:id,name')->get();
foreach ($posts as $post) { $post->user->name; }

29 Деплой

Выкладка на боевой сервер: собрал зависимости, закэшировал конфиги, прогнал миграции, поднял воркеры очередей. Прод работает как часы.

  • Forge / Vapor / Valet — окружения.
  • Перед деплоем: composer install --no-dev --optimize-autoloader.
  • На проде: php artisan config:cache, route:cache, view:cache.
  • php artisan migrate --force в проде.
  • Оптимизация: OPcache, php artisan optimize.
  • Режим техобслуживания: php artisan down/up.
  • Secret-ы только в .env, не коммитить .env.
  • Очереди на проде: супервизор для queue:work.
Настройка после деплоя
composer install --no-dev --optimize-autoloader
php artisan config:cache
php artisan route:cache
php artisan view:cache
php artisan migrate --force
php artisan optimize

30 Best Practices

Правила хорошего тона в Laravel: тонкие контроллеры, валидация в отдельном классе, всё медленное — в очередь. Именно это спрашивают на собесах.

  • Тонкие контроллеры, толстые модели/сервисы.
  • Бизнес-правила не в маршрутах и не в Blade.
  • Использовать env() только в config, остальное через config().
  • Валидация в Form Request, а не в контроллере.
  • Очереди для всего медленного (почта, отчёты).
  • Eager loading и проверка N+1.
  • Автотесты на ключевые сценарии.
  • Следить за версиями PHP/Laravel и обновляться безопасно.
  • Пользоваться Pint (форматтер) и PHPStan/Larastan (статический анализ).
